01 / voluntario

Resurrección del Chromebook N22

Transformé un Lenovo N22 con ChromeOS obsoleto en una máquina dual-boot con Windows 11 Pro y Arch Linux + Hyprland, configurándolo todo en un eMMC de 30 GB.

Voluntario Arch Linux Hyprland Hardware real Dual-boot
detalle ↓

El reto

Tenía un Lenovo N22 con ChromeOS descontinuado que ya no recibía actualizaciones. El hardware seguía funcionando, pero el software lo limitaba. Mi objetivo era convertirlo en una máquina completamente funcional para evitar tirarlo.

El problema técnico

El disco es un eMMC soldado de solo 30 GB. Instalar Windows 11 Pro y Arch Linux con Hyprland en ese espacio tan reducido me obligó a planificar cuidadosamente el particionado y a decidir qué instalar en cada sistema para que ambos fueran viables.

Proceso

  • Analicé el hardware y la compatibilidad de los drivers.
  • Desbloqueé el firmware del Chromebook.
  • Diseñé el esquema de particionado en los 30 GB disponibles.
  • Instalé Windows 11 Pro, ajustando el espacio al máximo.
  • Instalé manualmente Arch Linux desde cero.
  • Configuré Hyprland como el compositor Wayland.
  • Configuré el bootloader para gestionar el arranque dual.

Resultado

El equipo funciona con un sistema dual-boot completamente operativo entre Windows 11 Pro y Arch Linux con Hyprland. He documentado todo el proceso.

02 / académico ampliado

Instalación y configuración de Endeavour OS

Práctica de instalación del módulo SOM. Elegí Endeavour OS (basada en Arch) por su proximidad al sistema real. Instalada en hardware real.

Arch Linux Hardware real CC BY-NC-SA 4.0
detalle ↓

Contexto

Para una práctica de instalación del módulo SOM en 1º de SMR, elegí Endeavour OS. Es una distribución basada en Arch Linux que ofrece un instalador gráfico, pero sin llegar a ocultar la estructura interna del sistema operativo. La escogí para poder profundizar más allá del temario básico.

Por qué Endeavour OS

Aunque Arch Linux puro requiere una instalación manual desde la TTY, Endeavour mantiene la misma filosofía pero agiliza el proceso con su instalador gráfico. Esto me permitió estudiar cómo funciona el sistema real por debajo sin tener que invertir horas extra configurando el particionado a mano.

Contenido de la documentación

  • Realicé un análisis de la distribución y la comparé con otras opciones.
  • Documenté el proceso de instalación paso a paso, incluyendo las capturas de pantalla.
  • Añadí la configuración del entorno post-instalación.
  • Publiqué todo el material bajo la licencia CC BY-NC-SA 4.0.

Plataforma

Equipo físico con un procesador Intel Core i5-7500 a 3.40GHz y 8 GB de memoria RAM.

03 / personal · open source

Instalador Automático de Arch Linux

Script en Bash de producción: 3 fases de configuración interactiva, cifrado LUKS2, soporte BTRFS con subvolúmenes, 4 kernels, 6 entornos de escritorio y navegación hacia atrás sin perder estado. Arch Linux completamente instalado en 5–10 minutos.

Open Source Bash LUKS2 BTRFS Arch Linux set -euo pipefail
detalle ↓

El problema

Instalar Arch Linux a mano requiere introducir más de 30 comandos en un orden exacto: el particionado, el formateo, el montaje, pacstrap, arch-chroot, la configuración del gestor de arranque, la red, la zona horaria y los usuarios. Un solo error te obliga a empezar casi desde cero. Como instalo el sistema frecuentemente, necesitaba automatizar este proceso.

La solución

Escribí un archivo install.sh utilizando set -euo pipefail para asegurar una ejecución estricta y sin fallos silenciosos. El script recorre tres fases de configuración interactiva antes de aplicar cualquier cambio en el disco duro. En cualquier pregunta del proceso, puedes pulsar < y Enter para regresar al paso anterior sin perder los datos de las fases ya completadas.

Fase 1: El Sistema Base (11 decisiones)

  • Detección automática de los discos mediante lsblk.
  • Detección del firmware (UEFI o BIOS/Legacy) leyendo directamente desde /sys/firmware/efi.
  • Configuración del tamaño de la partición Swap, comprobando que quepa físicamente en el disco.
  • Cifrado mediante LUKS: LUKS2 con Argon2id para systemd-boot, y LUKS1 con SHA-256 para GRUB por compatibilidad. La partición Swap cifrada utiliza el PARTUUID para evitar arranques lentos.
  • Elección del sistema de archivos: ext4 clásico o btrfs, creando automáticamente los subvolúmenes @, @home, @snapshots y @log.
  • Creación de una partición /home separada si se usa ext4, calculando el espacio restante de forma dinámica.
  • Configuración del nombre del equipo, el idioma, la distribución del teclado y la zona horaria (validando esta última contra los archivos en /usr/share/zoneinfo/).
  • Selección del kernel: linux, linux-lts, linux-zen o linux-hardened.
  • Selección del gestor de arranque: GRUB o systemd-boot.

Fase 2: Usuarios y Seguridad

  • Creación del usuario principal y asignación automática a los grupos wheel, audio, video y storage.
  • Establecimiento de las contraseñas para root y para el usuario, ocultando la entrada y exigiendo una doble confirmación.

Fase 3: Entorno Gráfico y Paquetes Extra

  • Selección de los drivers de vídeo: Intel, AMD, NVIDIA, VirtualBox, VMware o ninguno para servidores.
  • Instalación del entorno de escritorio: GNOME, KDE Plasma, XFCE, Hyprland, i3-wm o ninguno.
  • Instalación del gestor de paquetes AUR: paru o yay.
  • Descarga de Dotfiles: Pide la URL de un repositorio Git y el nombre del script de instalación del usuario.
  • Servicio SSH: Permite habilitar el demonio sshd para que arranque con el sistema.

Arquitectura del script

  • Máquina de estados: Las variables HISTORIAL[] y PASO permiten retroceder de paso sin perder los datos ya introducidos.
  • Interfaz visual mediante colores ANSI: Implementé las funciones log(), warn(), error(), step() y pick() para mejorar la legibilidad en la consola TTY.
  • Validación de los datos: El script verifica que el disco exista realmente, que las contraseñas coincidan y que el tamaño indicado para la partición Swap no exceda la capacidad del disco.
  • Cero configuración posterior: Al terminar el script, el sistema arranca listo para usarse, incluyendo el entorno gráfico, el gestor AUR y las configuraciones personales del usuario.
